# R1 preliminary training experiment

## Status

R1-Fixed and R1-Width passed the 640 px smoke test and completed 100-epoch full training on four RTX 3090 GPUs.
No extra threshold tuning or variant was run.

## 1. Implementation changes

- Added `assignment_perturbation: dfl|fixed|width_matched` to the SSOD configuration and DDP forwarding keys.
- Moved the geometric candidate construction into `ultralytics/utils/assignment_stability.py`, so analysis and
  training call the same implementation.
- Fixed uses the analysis definition: independently move left/right edges by `0.05 * w` and top/bottom edges by
  `0.05 * h`, yielding the baseline plus eight candidates.
- Width-matched uses the analysis definition without alteration: for each object edge, compute `Q90-Q10` in DFL
  distance space, move symmetrically by half that width, clip to `[0, reg_max-1]`, and decode with the original
  anchor and stride. The baseline candidate is the original expected pseudo box.
- Baseline TaskAlignedAssigner output remains the assignment used for training. Stability only weights box and DFL
  terms and is normalized by the stability-weighted target-score sum. Classification, negative classification, and
  pseudo-label selection are unchanged. R2 ambiguous-negative ignore is not enabled.
- The launcher freezes the existing confidence-only baseline settings: YOLOv8n supervised checkpoint, CrowdHuman 5%,
  640 px, 100 epochs, labeled/unlabeled batch 128, workers 8, seed 0, deterministic mode, confidence thresholds
  0.5/0.3, SSOD weight 0.5, burn-in 0, and optimizer/augmentation/EMA defaults. The full runs used devices 0,1,2,3
  while retaining global batch 128.

## 4. Baseline versus R1

All rows are read from their saved `results.csv`.

| Method | Final mAP50 | Final mAP50:95 | Best mAP50 | Best mAP50:95 |
|---|---:|---:|---:|---:|
| Confidence-only SSOD | 0.75995 | 0.46834 | 0.76023 | 0.46848 |
| DFL-selection SSOD | 0.76035 | 0.46632 | 0.76068 | 0.46639 |
| R1-Fixed | 0.75952 | 0.46710 | 0.76017 | 0.46725 |

Against confidence-only, R1-Width is +0.00105 final mAP50 but -0.00072 final mAP50:95. Thus it is essentially tied:
the one-seed result does not establish an overall SSOD improvement.

## 5. Did R1-Width outperform R1-Fixed?

Yes, narrowly on all four saved point estimates. Width exceeds Fixed by +0.00148 final mAP50, +0.00052 final
mAP50:95, +0.00120 best mAP50, and +0.00049 best mAP50:95. These are small one-seed differences and should not be
described as statistically reliable.

## 7. Abnormal behavior

No NaN, inf, OOM, empty-weight collapse, pseudo-label-count divergence, or assignment-feedback path was observed.
The original long-running shell ended after R1-Width epoch 42. Standard resume initially exposed an existing SSOD
trainer defect: the frozen teacher was only created at epoch 0 and was absent on post-burn-in resume. Resume support
was fixed to require and restore the original supervised teacher checkpoint, after which epochs 43--100 completed.
The interruption therefore did not substitute the resumed student as teacher.

## 8. Whether to proceed to R2

R1-Width consistently edges R1-Fixed, so the adaptive-width responsibility signal is the preferable R1 definition.
However, its mAP50:95 remains 0.00072 below confidence-only and the gains over Fixed are only about 0.0005--0.0015.
R2 may be worth one frozen follow-up as a distinct hypothesis, but R1 alone does not yet provide evidence of a robust
SSOD improvement. Multiple seeds should precede a strong claim; neither R2 nor extra tuning was started here.

## Reproduction

From a terminal where `nvidia-smi` succeeds:

```bash
bash scripts/dfl_assignment/run_r1_preliminary.sh
```

The runs are sequential and write to `runs/r1_preliminary/r1_fixed` and `runs/r1_preliminary/r1_width`.
